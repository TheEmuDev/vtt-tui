The 28 s `netedges` suite is one test: "a watcher that never reads is dropped once its queue is
full" (`tests/test_net.c:2112-2136`) pushes whole-screen frames through loopback until the
kernel's socket buffers *and* the 64 KB user buffer are full (up to 512 MB). Its duration is the
kernel's buffer sizes, not vtt's. It is also the only test of the phone-drop path under
realistic conditions (see section 2).

Three things the run shows that the rewrite should not inherit: the compile is monolithic (a
one-line change recompiles 84 files for 50 s); the suite is wall-clock-bound by design (real
sockets, real `poll` timeouts, child processes polled with `poll(NULL, 0, 2)` spin loops capped
at 50-400 iterations, e.g. `tests/test_ctl.c:1328`, `:1499`), which is flake-by-construction
under load even if it did not flake in my three runs; and a coverage number of 91.8% hides the
fact that the five least-covered files are exactly the ones a 2.0 redesign touches (terminal,
channel client, the loop).

## 1. Testability gaps

Severity: **High** = the rewrite will reintroduce bugs here unless the seam exists from day one;
**Medium** = costs test time or test honesty today; **Low** = paper cut.

### T1 (High) The interactive loop is the one untested path, and B1/B2/R8 all land in it

**Read.** `main.c:572-685` is the loop: poll timeout folded from six `*_due` functions, `net_service`,
`ctl_service`, `app_tick`, signal drain, input drain, `app_events_flush`, `app_frame`. No test
calls it (HEALTH row 9; CODEMAP `main.c` row says so). The suite reaches the *pieces*: `ctllive`
holds a `wait` over a real socket, runs twenty hand-written turns of `ctl_service`+`app_tick`,
presses a key and calls `app_events_flush` "as main does" (`tests/test_ctl.c:1474-1505`) — so
the hold/flush contract is tested at the function level, but the loop's ordering (keys handled in
the drain never reaching the flush was step 5's bug) is re-asserted by hand in each test. Review
2's B1 (non-blocking terminal with a pending buffer and frame coalescing) and B2 (a per-turn
budget for requests) are both loop-body changes: with no `loop_once` function they will be
built and verified by driving a live vtt on a pty, as I had to (section 5).

### T2 (High) White-box tests poke struct fields: a rewrite breaks the suite before it breaks behavior

**Read.** Tests set `a.ed.cx`, `a.ctl_auto`, `a.job_last`, `n.cl[i].out_len`, `n.stale`,
`a.ctl.path`, `app_self_path` (a global), `t.out_fd`, `t.dead`, `r.force_full` directly
(`tests/test_jobs.c:830-833, 864`, `tests/test_net.c:835-836`, `tests/test_core.c:1560-1590`,
`tests/harness.c:457-461`). This is cheap and honest today, but it means most of the 19,173 checks
are bound to 1.x's data layout, not to its behavior. Section 3 says which parts of the suite can
be an oracle for 2.0 and which cannot; the short answer is that the black-box surfaces (goldens,
map tools, file round trips, channel transcripts, wire streams) can, and roughly the field-poking
half cannot.

### T3 (Medium) `App` is where the seams stop

**Read.** `src/app.h:118-363`: 124 `;`-terminated declarations by my count (review 1 said 134;
the difference is how arrays and nested structs are counted — **checked** by `awk`). The pure
modules are genuinely pure and tested without it: `test_changeset.c` and `test_maptools.c` declare
no `App` at all; `map`, `fog`, `undo`, `checkpoint`, `wire`, `json`, `mapio`, `ruler` take a
`Map*`/`Undo*`/`Renderer*`. But everything in `app_*.c` needs `App` plus a `Renderer`, and
`app_ctl_exec` needs the whole `App` because a proposal swaps `a->map`/`a->undo` for
`App.ctl_scratch`/`ctl_sundo` (`src/app_ctl.c:979-1056`, CODEMAP row) — so a request handler cannot
be tested without the editor, the jobs, the events, the net and the agent state in scope. This is
why `test_ctl.c` is 1,974 lines of `App` setup. Review 1's R8 (sub-structs `Channel`, `Jobs`,
`Disk`, `Events`) is necessary but not sufficient: the request handlers also need to take a
narrower "world" (map + undo + jobs + events) than `App*`, or every protocol test stays an
application test.

### T4 (Medium) Non-determinism is mostly behind seams already; three leaks

**Read.** Good: the clock is injected everywhere that matters (`app_tick(a, now_ms)`,
`net_service(..., now_ms)`, `ctl_service(..., now_ms)`, `net_frame_end(n, now_ms)`), so timeouts
(15 s keep-alive, 60 s idle, 10 s channel deadline, autosave quiet time, event quiet time) are
unit-tested with fake time (`tests/test_net.c:350-420`, `tests/test_core.c:2192+`). The dice are
seedable (`--seed`, `src/dice.h:23-26`). The agent is a shell command (`:agent command`), so a
**scripted fake agent exists**: `tests/test_jobs.c:838-847` writes a four-line `sh` script that
takes the job and proposes through the real `./vtt --ctl`; `test_agent_command` drives it end to
end, including feedback, SIGPIPE disposition and "nobody's child". Leaks: (i) `ctllive` and
`agentcmd` use `prof_now_ns()` (real time) and real `poll` sleeps because the socket layer has no
fake — there is no in-memory transport, so every channel/phone integration test is a real
loopback socket; (ii) the `--apply`/`--ctl` client probes every socket with a real 2 s deadline
(`CTL_FIND_MS`, `src/ctl.c:480`, `clock_gettime` at `:720-723`), which is why `--apply` tests
fork children and wait; (iii) `slog.c:16` stamps with `time(NULL)` (harmless: the log is not
asserted on).

### T5 (Medium) No fault injection anywhere

**Read.** `xmalloc` dies on OOM (`src/util.c:25-29`), so OOM is a policy, not a path. Nothing can
make `write`, `fsync`, `rename`, `fork`, `pipe`, `socket`, `accept` fail in a test (HEALTH row
41 says the same for `fork`). The only "failure" tests use the filesystem's permissions: a
read-only directory to fail a delete (`tests/test_core.c:1854`) and a rename (`tests/test_places.c:1429`).
Consequences in section 2: a failed save has defined behavior and no test; a failed autosave
has undefined (silent) behavior and no test; a failed `fork` for the agent is reported and
untested.

### T6 (Medium) The oracle for the players' frame is glyphs only

**Read.** `players_text()` (`tests/harness.c:444-453`) and every golden go through `rnd_dump`
(`src/render.c:253-265`), which writes the glyph of each cell and nothing of its colors or
attributes. A GM-only thing that reaches the phones as a *tint* (a job's box, a fog shade, a
selection highlight) is invisible to these checks; the tests that care read `r.back[]` by hand
(the tint tests in `test_jobs.c`, the contrast tests via `luminance()` in the harness). The rule
"every GM-only thing is added to `app_view_differs`" has no enumeration test (review 1 S2-3,
**checked**: `grep -c players_text tests/*.c` finds it in 12 files, and none lists the GM-only
set). For 2.0 the privacy property needs a cell-level oracle (glyph+fg+bg+attr) and a model of
"GM-only" that the test can enumerate.

### T7 (Medium) Goldens are few, small and wording-bound

**Read.** 16 frame goldens, all 72x20 except two (`tests/test_core.c:1430-1540`), plus 14 tool
reports (`tests/golden/*.txt`, 30 files). They are regenerated with one env var
(`VTT_UPDATE_GOLDEN=1`), the diff printer shows the first differing line, and `golden_bytes` is
reused for the map tools' text — all good. Brittleness: the status line and key bar are in every
frame, so any reworded hint or re-ordered bar changes most goldens at once; the width is fixed
so layout at other widths is covered by one `narrow` frame; colors are not in the oracle (T6).
For 2.0 they are an excellent *regression* oracle for the renderer and the map tools (section 3),
and a poor one for the UI text.

### T8 (Medium) Prose is the contract, so tests pin prose

**Read.** Verdicts and events are sentences (`src/app_ctl.c:1498-1499`; review 1 S1-1,
**checked**). The suite therefore pins wording with `strstr`/`strncmp` in hundreds of places
(`tests/test_ctl.c:1371, 1423`, `tests/test_jobs.c:852-863`, …), and the program's own client
scrapes the same words (`src/ctl.c:622-645`; HEALTH row 16). Every reword is a suite-wide edit
and a silent `--wait` break. Review 1's R2 (codes) makes the tests match codes and keep the prose
as the body; without it, 2.0's protocol tests will be as brittle as 1.x's.

### T9 (Low) Fork-based client tests hide failures

**Read.** `ctl_client_main` runs in a forked child that `_exit`s (`tests/test_ctl.c:1404-1411,
1437-1442`). ASan reports in the child go to the redirected fd and are not counted; gcov data is
not written (hence `ctl.c` at 47%). An in-process client (a function taking a socket path and
returning the answer) would test the same code without the fork.

### T10 (Low) Global state in the test process

**Read.** `app_self_path` (set and restored by hand, `tests/test_jobs.c:830, 1018`),
`draw_set_ascii` (`tests/harness.c:80, 109`), the dice generator, the profiler, `static int told`
in `press_balanced` (`tests/harness.c:134`), `static uint8_t seen[64*64]` in the fog differential
(`tests/test_fog.c:720`). None caused a failure; all make suites order-dependent in principle.
Running suites alone (`build/run-tests NAME`) is the mitigation and it worked for all 170.

### What is already right, and should be carried over unchanged

- `press()` enforcing `undo_balanced` after every key (`tests/harness.c:129-151`): an invariant
  checked on every keystroke of every test, for free.
- The fog **differential test** (`test_fog_diff`, `tests/test_fog.c:739+`): random ops against a
  slow definition (`fd_check`), with a knob for a long run (`VTT_FOGDIFF_OPS`). This is the
  pattern 2.0's overlay, sparse rows and `changes` need (section 3).
- The loader fuzzer's **round-trip oracle** (`tests/fuzz_mapio.c:62-93`: whatever loads must
  save, load and save to the same bytes) — it found B11.
- The channel fuzzer's **verdict invariant** (`tests/fuzz_ctl.c:50`: the first line is always
  `ok`/`error: `/`busy: `) and its undo-everything reset.
- `sandbox_enter` (`tests/harness.c:157-185`) and the canary check in tests/CLAUDE.md; HEALTH's
  *Disproved* row explains why it exists.
- Fake time everywhere a timeout lives (T4).
- The scripted fake agent (T4) and `--apply` as the same request language for file and live.
- `tests/fixtures/broken.vtt` carrying one of every loader finding, with `check-broken.txt` and
  `check-broken-json.txt` as goldens.
- The page decoder cross-check in node (`tests/page_feed.js`, `test_page_feed`) and the wasm
  blitter's "is the one tools/blit_wasm.py assembles" check: the phone's JavaScript and wasm are
  covered by a third decoder, not by eye.

## 3. Testing strategy for 2.0

### 3.1 Before the first line of 2.0: freeze the oracles

The rewrite needs a record of 1.x behavior that does not depend on 1.x's structs. Build it from
the surfaces that are already black-box, with a script that runs the **1.x binary** and stores
the outputs:

1. **Map tools** over every fixture, every `tests/fuzz-found/*.vtt`, and a generated set
   (`tools/genmap.sh` at several sizes, plus mutated copies): `--check` and `--check --json`,
   `--describe` and `--describe --json`, `--dump-map` whole and by region. Stable codes make
   `--check` the strongest oracle in the repo.
2. **File round trips**: for each input, `load → save` bytes (the fuzzer's property, run over a
   corpus and stored). This pins the writer's "lowest version that says everything" rule.
3. **Frames**: `--script KEYS --dump-frame --size WxH` for each golden's script and a few more
   widths (**reproduced**: two runs of the same script give identical 3,536-byte frames). Add a
   cell-level dump (glyph, fg, bg, attr) to 1.x first — a 30-line addition to `rnd_dump` — so
   colors are in the oracle too (T6).
4. **Channel transcripts**: every request text in `tests/test_ctl.c`, `test_jobs.c` and the
   `tests/fuzz-ctl/` corpus, run through `app_ctl_exec` (via `--apply` or a tiny driver) against
   a known map with `ctl_auto` on and off, storing `request → answer`. When R2 adds codes, the
   comparison is "same prose after the code".
5. **Wire streams**: `--bench-record` per perf scenario, decoded by the C decoder and by the page
   (`tests/page_feed.js`) — both decoders must still agree on 2.0's streams if the wire is kept.
6. **AGENTS.md's example plan** (`tests/test_ctl.c:1197-1211`) and `apply-crypt.txt`.

What **cannot** serve as an oracle: tests that set or read struct fields (T2); tests that pin
the loop's turn-by-turn ordering by hand; the timing-bound socket tests (their *assertions* are
good, their *mechanics* are 1.x's); the goldens' status-line text if 2.0 rewords hints (keep
the map area of each golden as the oracle, treat the bar separately).

Then the proof is a **differential run**: `git worktree add /tmp/prev` of 1.x, both binaries over
the same corpora, outputs compared. This is what the repo already does for perf (CLAUDE.md,
*Commands*); extend it to behavior.

### 3.2 Seams the design must have from day one

Each is a type with one production implementation and one test implementation; none needs a
library.

- **Clock**: `now_ms` passed in, as today, and *no* `clock_gettime`/`time()` outside `main` and
  `prof`. The client's 2 s probe (`CTL_FIND_MS`) takes a deadline, not a sleep.
- **Loop body**: `loop_once(App*, const Ready* ready, uint64_t now_ms)` where `Ready` is what
  `poll` said (which fds, what events). A test builds `Ready` by hand; `main` builds it from
  `poll`. This is R8's `app_loop_once`, and it is where B1's pending buffer, B2's budget and the
  hold/flush contract become unit-testable.
- **Output sink**: the terminal as `{fd, pending buffer, write(), poll-wants-POLLOUT}`; a test
  implementation is a pipe nobody reads (stall) or a memory buffer (assert bytes). The renderer
  already keeps `front` honest on a short write; the sink must preserve that.
- **Transport**: channel and phones over a `Conn` abstraction (read bytes, write bytes, closed)
  so protocol tests run on `socketpair()` or memory pipes with fake time, and the real socket
  code is tested separately and once. Sockets today are tested only through real loopback (T4).
- **Spawner**: `spawn(cmd, env, stdin_bytes) -> pid or error`, one implementation (HEALTH 38
  wants it anyway), so a test can make it fail (HEALTH 41) or substitute a fake agent.
- **Disk**: `{open, write, fsync, rename, unlink, stat}` behind one struct so ENOSPC/EIO/EROFS
  are one line in a test; `mapio` and the autosave use it.
- **World**: the request handlers take `(World*, args, FILE* out)` where `World` is map + undo +
  jobs + events (+ the scratch overlay), **not** `App*` (T3). `REQUESTS[]` (R1) is a table of
  these handlers; the dispatcher is a loop. The channel, `--apply`, the fuzzer, the bench and
  the tests call the same function.
- **Privacy model**: one function that, given the `App`, lists the GM-only elements on screen
  (what `app_view_differs` decides from), so a test can assert "no cell the model calls GM-only
  differs from blank in the players' frame" on every simulated frame.
- **Author on every undo op** (or on every landing): a small stamp (`agent id`, `job`, `seq`)
  so "who changed this square" is answerable (section 4) and `job N undo` has something to check.

### 3.3 The layers, in build order

1. **Pure modules first, with property tests** (weeks 1-2): map, fog, sight, undo, changeset,
   checkpoint/overlay, ruler, wire, json, mapio. Carry over the existing module tests nearly
   verbatim (they take `Map*`, not `App*`). Add properties, each a randomized loop with a seed
   printed on failure, in the shape of `test_fog_diff`:
   - round trip: `save(load(f)) == save(load(save(load(f))))` (the fuzzer's), over corpora;
   - undo/redo: random op sequence, undo all, map equals start; redo all, map equals end;
   - change set: `apply(diff(a, b), a) == b`; `apply(inverse(cs), apply(cs, a)) == a`;
   - **overlay vs copy** (review 2 P3): random edits on a COW overlay over a base equal the same
     edits on a full copy; the overlay's noted cells equal the diff;
   - **sparse rows vs dense** (review 2 B3): the two encodings of the same map load to equal maps;
     a map that needs no sparse row saves byte-identical to 1.x (differential run);
   - fog: keep `fd_check`.
2. **Protocol** (weeks 2-3): transcript tests over `exec(World, request)`: one data file per verb
   with request and expected answer; the AGENTS.md verb table vs `REQUESTS[]`; `help json`
   validates; `fuzz-ctl` kept with its invariant extended to "the first line carries a code".
   Multi-agent state machine tests here, with two `World` clients: propose, review, accept,
   refuse, feedback, conflict (`cs_check`), `job N undo`, `lost A-B`/`reset N` on the ring,
   `changes SEQ` equals the ChangeSet. No sockets.
3. **Simulation** (weeks 3-4): a deterministic driver around `loop_once`: scripted keys, scripted
   `Conn` bytes from N fake agents and M fake phones, fake clock, fault schedule for the Disk and
   Spawner seams. Scenarios: the stalled terminal (pending grows, phones still served, agents
   answered); the stalled phone (N frames → FULL); the budget (four dumps in one turn, keys
   still handled); the dead agent (job returns to asked after the deadline); the failed autosave
   (said once); two vtts on one file; the trip through a link with jobs open; `--apply --wait`
   while the vtt quits. The privacy model asserted on every simulated frame.
4. **End to end, few and slow** (ongoing, nightly): `agentcmd` with the scripted fake agent
   (exists); `ctllive` on real sockets (exists); the page decoder in node (exists); a **pty
   test** (what `live.py` in my scratchpad does: a real vtt on a pty, keys written, `--ctl`
   probed; sandboxed) for the loop on a real terminal, including a paused reader for B1.
5. **Performance as tests** (with 3): the bench gains an allocation counter (review 2's shim as a
   first-class flag) asserting zero mallocs across frame loops; bytes-per-frame and
   bytes-per-phone-frame asserted per scenario within a tolerance (bytes are deterministic;
   times are not); `--bench-stall`; `ctl.wait` row (HEALTH 8) once the loop is a function.
6. **Lint** (R7) under `make test`: the greps the repo already states as rules, plus "no
   `clock_gettime` outside main/prof", "every `client_flush` caller checks -1", "every new
   `src/*.c` has a CODEMAP row".

Build hygiene for the suite itself: compile test objects separately so a change recompiles one
file; mark the slow suites (`netedges`, `agentcmd`, `ctllive`, `netmsg`, `netserver`) as a
second tier run by `make test` but skippable with `make test-fast`; cap the never-reads test at
the user buffer by setting `SO_SNDBUF`/`SO_RCVBUF` small on both ends (its intent is the 64 KB
bound, not the kernel's megabytes); put the fuzz-found inputs in the corpus the moment B11 is
fixed; add the three untested diag codes (E001, N105, W024) and the six missing file versions to
`broken.vtt`'s siblings.

## 4. Observability: debugging a bad session from its artifacts

What exists (**read**): the session log (`:log`) keeps every `app_note` with a `[HH:MM]` stamp,
one `fflush` per line so it survives a crash (`src/slog.c:53-66`); the event ring of 32 with
`seq`, `lost`, `reset` (`src/app_event.c:36-57`); `jobs [json]` with each job's thread (8 lines,
oldest dropped without a marker — review 1 S1-7, **checked** at `src/app_job.c:59-62`); the
`#N accepted: …` and `the agent took back its last change` notes on the GM's line (logged);
`--check`'s stable codes with line/column; `diag()` with slugs; `PROF_ZONE`/`--trace`/F12 for
time and bytes; the autosave as a crash artifact; `--describe --json`.

What is missing to answer the four questions the brief asks:

- **Why was an agent's request refused?** Only the agent knows: `app_ctl_exec` writes the
  verdict to the socket and nowhere else (`src/app_ctl.c:1497-1507`; no `slog_write` or
  `app_note` on the error path — **read**: `slog_write` is called from two places in `app.c`
  only). A GM reading the log after a session sees accepted proposals and never the twenty
  refusals that preceded them. 2.0: a request log line per request (`[time] agent A: VERB… →
  code`) in the session log, or a `requests` ring beside the events.
- **What did a proposal change?** While the job lives: `job N dump/check/describe` and the
  ChangeSet. Once accepted: the note's summary line (`ground in A1`) and the undo log, which
  has no per-op author. The ChangeSet is kept with the job until the job is removed, but nothing
  writes it to the log. 2.0: on landing, append the `changes`-format lines (R3) to the session
  log, bounded.
- **Who changed a square?** Not answerable. `ctl_stamp`/`ctl_gen` is one scalar for "the
  agent's last change" (`src/app_job.c:125-129`); ops carry no author. 2.0: an author/job stamp
  on each undo mark.
- **What state was the loop in when it stalled?** Nothing. 2.0: on `SIGTERM`/fatal and on
  request, dump the event ring, the jobs, the pending-output size, the last ten requests and
  the `app_ctl_busy` reason to the session log (`on_fatal` already runs on the way out).

Smaller gaps: `status` has no `seq` (R3); the thread drops its middle silently; the
"started: … output in the log" line for an agent is the only trace of a spawn; the client's
"no vtt is taking requests" covers at least two different server-side failures (section 5).

## 5. The reproductions

All on the release `vtt` built by `make test` in `test-build/`, driven by
`scratchpad/live.py SANDBOX VTT a|b`: it opens a 100x30 pty, starts `vtt blank.vtt` (a 20x12
floor map) on it with `XDG_DATA_HOME` in the sandbox and `XDG_RUNTIME_DIR` in a fresh
`mkdtemp(/tmp/vtt-r3-XXXXXX)`, types `:agent on`, and runs `vtt --ctl REQ` with the same
environment, timing each; it stops the one PID it started and removes the runtime dir.

**Incidental (S1-8, reproduced).** My first attempt put `XDG_RUNTIME_DIR` under the scratchpad
(`…/scratchpad/live-b/rt`, 118 bytes with `/vtt/PID.sock`). `:agent on` could not listen, and
every `vtt --ctl` said `vtt: no vtt is taking requests - type :agent on in the one you mean`,
exit 2 — the server's reason never reached the client. (I did not capture the server's status
line.)

### (a) `wait 0` stalls on a fresh vtt — **confirmed**

```
$ vtt --ctl 'status'          -> exit=0 after 0.00s   (… agent on)
$ vtt --ctl 'wait 0 for 0'    -> exit=0 after 0.00s   seq 0
$ vtt --ctl 'wait 0 for 3'    -> exit=0 after 3.00s   seq 0
$ vtt --ctl 'wait 0'          -> exit=0 after 60.06s  seq 0
-- after `propose "a puddle"\ntile A1 water` (proposal #1 created) --
$ vtt --ctl 'wait 0 for 3'    -> exit=0 after 3.00s   seq 0
```

Cause (**read**): `app_ctl.c:1250` answers at once only if `app_events_after(a, seq)` is non-zero,
and `app_event.c:36-40` returns `event_seq - after` = 0 when nothing has happened; the default
hold is `CTL_WAIT_DEFAULT_S` = 60. AGENTS.md:268 ("`wait 0` everything still kept") describes the
`for 0` form. Also shown: an agent's own proposal makes no event (seq stays 0), so a second agent
would not hear of it either.

### (b) `undo` over the channel during the GM's review — **confirmed**

```
$ vtt --ctl 'propose "job one"\ntile A1 water'   -> proposal #1: ground in A1
   GM: :review 1 ⏎   then  ⏎ (enter accepts)
$ vtt --ctl 'jobs'      -> #1 accepted, an agent's own: job one
$ vtt --ctl 'dump A1:B1' -> 1  ~ .
$ vtt --ctl 'propose "job two"\ntile B2 water'   -> proposal #2: ground in B2
   GM: :review 2 ⏎   (the GM is now in ED_REVIEW on job 2)
$ vtt --ctl 'status'    -> screen build, review mode / undo 1 back, 0 forward
$ vtt --ctl 'undo'      -> exit=0  took back the last change
$ vtt --ctl 'status'    -> screen build, review mode / undo 0 back, 1 forward
$ vtt --ctl 'dump A1:B1' -> 1  . .
$ vtt --ctl 'jobs'      -> #1 accepted …  #2 ready …
```

The GM's status line read `the agent took back its last change - ctrl-r puts it back` over the
open review. Cause (**read**): `app_ctl_busy` (`src/app_ctl.c:99-111`) lists prompt, picker,
modal, `:` line, pending key and open wall stroke, not `ED_REVIEW`; `undo` (`:1193-1215`) asks
only it. CONFLICTS.md:101-106 chose "`u` works during review" and the preview-never-applied
design, so a landing during review is deliberate (HEALTH 28); whether an *agent's* undo during
review is too is undecided.

### (c) The phone paths review 2 could not exercise

- **The drop path is tested**: `tests/test_net.c:2112-2136` (queue overflow through a real
  never-read socket; it is the 28 s suite) and `:834-843` (`out_len` set near the cap by hand, a
  FULL forced, the client gone and the other still served). What is **not** tested is B8's
  property: how many frames of backlog a phone can accumulate before it is resynced — no test
  asserts a bound in frames, and there is none in the code.
- **The 128 KB FULL overflow — reproduced** with `scratchpad/overflow.c` linked against the
  release objects (`build/*.o` less `main.o`): a renderer of WxH cells, every cell a different
  fg and bg, `net_start`, a local raw watcher's hello, five turns of `net_service`:

```
window 300x60: a FULL is  37,886 bytes (cap 131,072)  clients=1  dropped=0  the watcher read a frame
window 200x50: a FULL is  21,786 bytes               clients=1  dropped=0
window 400x170: a FULL is 138,986 bytes (cap 131,072) clients=0  dropped=0  the watcher read 0 bytes (EOF: it was closed)
window 500x140: a FULL is 142,686 bytes               clients=0  dropped=0  EOF
window 512x200: a FULL is 208,086 bytes               clients=0  dropped=0  EOF
```

  So the close is real and **silent** (no `dropped` count, no GM message; `src/net.c:351-354`),
  but review 2's size estimate is **disproved**: a color per cell costs ~2 bytes a cell, not
  ~10 (the palette is indexed), so the cap is reached near 64K cells (400x160), not at 200x50.
  Severity Low; the finding is the silence, and that the buffer is a constant rather than the
  window's size. A unit test is 20 lines: the harness above with `CHECK_EQ(n.dropped, 1)` once
  the close is counted.

## 6. Verification of reviews 1 and 2's recommendations

One line each: how it is tested in 2.0, and what it makes easier (+) or harder (−) to test.

**Review 1**
- **R1 `REQUESTS[]`**: a test walks the table and asserts AGENTS.md/README list exactly its verbs;
  `help json` validates; each handler has a transcript file. + the dispatcher is data; − nothing.
- **R2 codes + JSON envelope**: transcript tests match `code`, prose compared separately; a test
  feeds real emitted events to `ctl_verdict_in` (closes HEALTH 16). + ends the `strstr` suite.
- **R3 `changes SEQ`, `status seq`, dump caps**: property `apply(changes(SEQ..now)) == map now`
  against a kept snapshot; `wait 0` answers at once (the (a) script becomes a test); dump above N
  refused with a code. + the delta read is itself an oracle for the overlay/ring.
- **R4 identity, `job N undo`, review guard, pid table**: two-client protocol tests (own/other's
  job; undo while reviewing; a second run of a job refused); the (b) script becomes a test.
  − needs the two-connection fixture (socketpair, no real sockets).
- **R5 conflicts as data**: `job N conflicts` equals `cs_check`'s list after a scripted GM edit;
  closes HEALTH 3's gap too.
- **R6 docs truth vs history, R7 lint**: lint is the test; make it fail on a known seed violation
  first (a lint that has never failed proves nothing).
- **R8 split `App`, `app_loop_once`**: the simulation layer exists only because of this; test by
  driving it with fake `Ready` sets and asserting the order keys → tick → flush → frame.
  + everything in section 3.3 step 3.
- **R9 MCP outside the binary**: untested by vtt; a schema-from-`help json` check in the wrapper's
  own repo.

**Review 2**
- **B1 non-blocking terminal, pending buffer, coalescing**: sink seam; tests: a pipe nobody
  reads — frames drawn, pending grows, phones and channel still answered in the same turn; then
  drain — the screen equals a full repaint of the *latest* frame (coalescing correctness is a
  renderer property: compare against `rnd_dump`). `--bench-stall`. − the renderer's "front equals
  delivered" invariant becomes stateful; test it as a property over random short writes.
- **B2 per-turn budget**: with four fake agents each requesting `dump`, one `loop_once` handles
  the key and draws before the fourth answer completes; answers still arrive whole and in order.
  − streaming answers across turns means a read spanning turns must snapshot; test that a map
  edit between turns does not tear a dump.
- **B3 sparse rows behind a version, deferred fsync**: differential load of dense vs sparse; byte
  identity with 1.x for maps that need no sparse row; the Disk seam asserts `fsync` is called by
  the next turn / on close and not on the key; a crash-between test with the seam.
- **B4 creature indices/caches**: property: the cached answer equals the O(n) walk after random
  edits (gen-stamp invalidation is the bug class).
- **B5 keep two renderers**: the privacy model test (section 3.2) on every simulated frame.
- **B6/P3 one COW overlay type**: overlay vs full-copy differential (section 3.3 step 1); the
  diff equals the overlay's noted cells.
- **B7 persistent connections**: protocol tests on `socketpair`; a dropped connection mid-request
  leaves the world unchanged; identity follows the connection.
- **B8 lag bound in frames**: fake time, never-read `Conn`, assert FULL after N frames; retire the
  28 s kernel-buffer test to the slow tier.
- **B9 frame buffer from the window**: the overflow harness as a test; `dropped`/a note on close.
- **B10 picker sort+dedup**, **B11 undo ring**, **B12 posix_spawn**: B10 and B11 are pure
  functions — property tests (dedup equals the quadratic one; ring equals the memmove log over
  random ops past the trim). B12 goes behind the Spawner seam (section 3.2); the `agentcmd` test
  stays as the real-process check.
- **Allocation-free frames as an invariant**: the bench's counter asserted in `make test` on two
  scenarios (a cursor walk, play with 500 creatures).

## 7. Open questions for the maintainer

1. **Is behavior-equality with 1.x the goal, or behavior-compatibility?** Section 3.1's
   differential run needs the answer per surface: must `--check`, `--describe`, `--dump-map`
   and the file bytes match exactly (strong oracle, cheap), or only the channel's semantics
   (codes added, prose free to change)?
2. **Is an agent's `undo` during the GM's review allowed** (as a landing during another review
   is, HEALTH 28), or does `ED_REVIEW` count as busy for undo? Reproduction (b) is undefined
   today.
3. **Should `wait 0` with nothing kept answer at once**, or should the doc say `wait 0 for 0`?
   And should an agent's own proposal be an event (a second agent hears nothing today)?
4. **May the suite gain a slow tier** (`make test` runs everything; `make test-fast` skips the
   five socket/process suites, ~45 s of the 62), given "no build tool beyond make"?
5. **Fault injection by seams** (Disk, Spawner, Transport, Clock as structs with one production
   implementation) — acceptable in a "nothing beyond libc" codebase, or must failures stay
   untested as HEALTH 41 records?
6. **Should a failed autosave be told to the GM?** Today it is silent by design ("marked
   attempted so the loop does not spin"); the silence is the data-loss path.
7. **What does the session log record in 2.0**: notes only (today), or every request and its
   verdict, every landing's change lines, and a dump on fatal? It costs a line per request.
8. **Does "who changed this square" need an answer** (an author stamp on undo marks, R4's
   prerequisite), or is "the agent's last change" enough?
9. **Cell-level goldens** (glyph+colors) — may 1.x gain the dump before the rewrite, so colors
   are in the oracle and the GM-only tint test is black-box?
10. **A pty-driven end-to-end test in `tools/`** (what `live.py` does) — wanted in the repo as the
    one test of the real loop, or does the loop become testable enough (R8) that none is needed?
11. **Which file versions must 2.0 load?** Fixtures cover 1, 2, 6-9, 13, 14; if all fourteen,
    the missing six need fixtures before the loader is rewritten.
12. **Is the silent close of a phone whose FULL exceeds the cap acceptable** at ~64K cells
    (never on a terminal), or should the cap follow the window and the close be counted?
