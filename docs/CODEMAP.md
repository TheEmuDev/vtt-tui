# Code map

What each file owns, the invariants that live with it, every command, the conventions with
their reasons, and the tech debt left on purpose. CLAUDE.md holds the rules; this is the
reference it points to. **Do not read this file whole**: take the rows you need, e.g.
`grep -n 'fog\.c' docs/CODEMAP.md`, or search it for a function's name.

A row is part of the change that makes it untrue: a new source file gets a row, a moved
responsibility moves its sentence. Reviews check this (docs/HEALTH.md, *The questions*).

| `maptools.c` | headless map tools behind `--dump-map` (and `--check`, `--describe`; **a `Finding` owns its `msg` and `where`**, made by `finding_say`/`finding_where`, freed by `finding_free`, moved by `take_finding`, never written straight; a section with a line too many or too few is scored at every place the fix could go (`shift_find` decides which: the file's form by its sections -- two or more ending in exactly one blank and it keeps separators, each set aside, a section then one short not searched; fewer and a blank after a section is a pushed-out row; a section whose count is wrong for certain outranks one that only ends in a blank; a header seen twice, nothing). `shift_search`: a band per row reads the suspect's rows y-1 and y, so two running sums and a seam score each candidate; a run of like rows is one candidate; a line too many is only ever an empty line or a copy of its neighbor (or the last) -- a row with a twin elsewhere in the section (what a paste makes) is scored as a shadow, never told, and one within the tie of the best leaves no place sure; two sections wrong for certain tell no place; an answer resting only on a section's trailing blank (`blank_only`) needs a fix that leaves nothing counted, says "unless that is a separator" and is never certain -- and where other sections end in an empty row (vtt's form, one section ending in a blank: witnesses) `shift_joint` scores the other reading, each witness having lost a row, and if it fits as well both are said with no place (`either`), its fold the first reading's and said so (`fold_if`); **every answer is weighed by `shift_joint`** against its section fixed anywhere else together with a row lost from a section whose last row as loaded is blank with only blanks after it (a loss a separator hides; one such loss, not two), and if that fits as well no place is told -- `shift_joint` asks whether some pair of places fits within a limit: four running sums (each section as read or moved) bound every pair from below, a seam is read only for a pair the sums leave within it, both together where they meet, and the first fit ends it (checked against a brute force over the suite's calls, outside the suite: HEALTH 83); a lost row comes back empty or as a neighbor's copy; within `SHIFT_TIE` is a tie, reported as a span. A place is told only by a margin over leaving it as read of more than the tie and twice what the fix still leaves, with walls or things taken off void (or, with `use_open`, open edges closed) -- loose ends alone place nothing; a line too many or a lost row only when the fix leaves nothing counted (a map's own flaws can make a wrong place score better than the true one: `flawed`), a lost row else told without a place (`nowhere`; `quiet` when nothing on the map tells the places apart), its fold a tie's (any place gives the same file below the section); a line too many for certain -- a line past the rows the loader reads as a stray row (`rows_past`) -- with no place told is said by its count and lines (`say_count`, every such section, folding the loader's W019s past its rows); a line past a section's rows that is neither blank nor a row is the loader's W015, set aside by `mapio_sections` (`dropped`); a count is exact only when every line past the rows is a row (else "at least"), and said only when each row section has its header once; a blank line is `MapioLine.blank` (only spaces) and a row-like one `MapioLine.row`, the loader's own readings; a fix that adds open edges is vetoed. The counts are check_map's -- walls on void, loose wall ends, creatures/notes/link ends on void -- and floor against void inside the map with no wall (`SH_OPEN`), which counts only when the fix it points to leaves none (a map drawn with walls; a cave has it everywhere). Never fog, whose patches may lie on void. Its finding is `W031` or the loader's `E011` told more; the fold reads the text again with the fix and checks it, and a finding the second check lacks (the suspect's own boundaries moved back across the seam first) is counted in it, not listed; on a tie only the file's findings fold. A finding's lines past its first are `FindingMore` (snippet, evidence, help, note, folded, span, certain), out of line. **The open map's report** (`maptools_check_open`, for `:check` and the channel): the file's findings from `Map.base` with the line search and its fold, checked on the map the bytes make, then the live map's own less those the fold explains (`FoldKey`s sorted once and searched: a map walled on every edge has a finding a square); an open's `MaptoolsFile` collects the loader's findings in its one pass, and `maptools_file_finish` (or `maptools_file_of`, reading `Map.base` again) runs the line search and gives the count, the first finding, and the line of a row added or lost. **Every code has its help** (`CODE_HELP`, looked up by the code's number in `code_help`; a row a slug where a code has two meanings): the text report says it once a code, under the first finding; the JSON in a top-level `codes` object; a finding's own `FindingMore.help` (the line search's) instead. Suite `checkhelp` reads src/ for every code and slug emitted and fails on one with no row. **One mistake, one finding:** boundaries with no map either side are reported by stretch (`void_edges_report`: union-find over shared corners), a stretch with a door being the door's E101 with the rest folded in, one of walls alone a W103 with its count and ends; a creature off the edge and on void is one E111. `Finding.count` is what a finding stands for, and the line search's fold tally sums it. |

## Conventions, with their reasons

- Opening the map the app will hold is `mapio_load_base` (it keeps the file's bytes and
  identity); anything that only reads a map file is `mapio_load`. A save of the open map is
  `app_save_map` (it refuses over an unreviewed change on disk; `App.file.save_force` is `:w!`).
- Status messages: `app_note` for things that *happened* (logged), `app_set_status`
  for hints and errors. Anything that puts a map down goes through `app_close_map`; the three places a map leaves the app's hands (`app_close_map`, `app_travel_to`, `app_open_map` over a map in hand) each send `map closed` and `world_jobs_clear` -- a fourth must too;
  anything that might discard work asks via `app_leave_map_for` (which `:e` uses).
- A prompt whose answer lands in a fixed field sets `a->prompt.max` to the field size.
- Every frame goes through `app_frame` (main, the bench and the net tests alike): the
  GM's view to the terminal, then the players' frame to the clients from `Net.players`,
  drawn with `app_draw_view(a, VIEW_PLAYERS)` when `app_view_differs` says the two
  could differ, else copied from the GM's back buffer. `a->view` is what is being drawn;
  GM-only things (modals, prompts, the profiler, the `(note)` hint, counters, a status
  message set with `app_note_gm`) check it. Add any
  new GM-only thing to `app_view_differs` too, or it reaches the phones. Build mode is
  the GM's alone. Whether the players may see a creature is one question,
  `fog_token_unseen(m, t, fog_any)` (its `Token.hidden` flag or fog over it): every
  players' path asks it, never `fog_token_hidden` alone. While any creature is hidden the
  players' frame is drawn (never copied), carries no status message, and gets the plain
  status line (no count, no ruler or range line), as over fog.
- Ideas consciously set aside live in `docs/IDEAS.md` with the reason (the Fear pool).
- Distances print through `dist_fmt`; coordinates through `map_coord_name`; a
  creature in a message through `token_name` (label, else its side). Overlap is
  `token_meets` / `tokens_at` / `tokens_overlapping`, never written out again. A label in
  a list is `tokens_find_label`; the same creature in two lists (a scene, a copy) is
  `token_same_key`.
- `range_clear` resets the overlay; `range_off` switches it off and keeps the shape.
- The `Cell` padding must stay zero (row memcmp in the renderer); tokens compare
  with `token_equal`, never `memcmp`.
- American spelling everywhere -- docs, messages, comments, identifiers (color, center,
  gray, canceled, labeled, counterclockwise). The loader still reads a marker saved as
  `grey`.
- Comments explain *why*; code says what. Rationale lives in the header or the README,
  not repeated at every call site.
- Never `pkill -f <pattern>` from a Bash call whose own command line contains the
  pattern: it kills the shell running it (exit 144). Record PIDs instead.
- To drive a live `vtt` from a script: `mkfifo f; (sleep 3600 > f &); script -qfc "./vtt map --serve 7792" /dev/null < f &`
  then `printf 'l' > f`. Chrome (via the claude-in-chrome skill) can open the served page.
- Environment quirks: `grep` is aliased oddly in this shell (use `awk` or plain
  `grep -n` in a subshell); `ESC` + letter in a script means Alt; scratch files go in
  the session scratchpad, not the repo.
