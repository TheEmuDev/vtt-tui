## What the reviews say, in one paragraph

The leaves are good and the spine is not. The renderer, the wire to the phones, fog and
sight, the undo op, the change set and the proposal model were each measured or read and
found at or near the floor; the reviewers ask that they be carried over unchanged. What they
ask to be rebuilt is everything those leaves hang from: the loop (`main.c`, untested, and
blocking on the terminal), the 200-declaration `App`, the channel's protocol (prose where
codes should be, a grammar kept in six hand-written lists), the file's density, and the
absence of any seam a test can put a fault through. So "full rewrite" has two readings, and
the first decision below is which.

## Decisions

Each gives the choice, the road not taken and what it costs.

**D1. The shape of the rewrite: rebuild the spine, carry the leaves.** *(the user's to
confirm, question 1)* A new `src/` is laid down in the order of *Build order*; the pure
modules (`map`, `fog`, `sight`, `undo`, `changeset`, `checkpoint`, `ruler`, `wire`, `json`,
`render`, `grid`, `dice`, `card`) move in with their tests, changed only where a decision
below names them; everything `app_*`, `main`, `ctl`, `net`'s service loop, `term` and `mapio`'s
writer is written again against the new structure. The other road is a clean room: every
line rewritten. It costs about 35 KLOC and the 19,173 checks to reach where the leaves
already are, and three reviewers found nothing in those files to fix. It buys a uniform
style and nothing measurable.

**D2. `World`, and a loop that is a function.** `App` splits along the seams its own
comments draw (`app.h:240-262`): `World` (map, undo, jobs, events, the overlay) is what a
request handler takes; `Channel`, `Net`, `Disk`, `Editor` and `Play` hold the rest. The
loop's body becomes `loop_once(App *, const Ready *, uint64_t now_ms)`, `Ready` being what
`poll` said; `main` builds it from `poll`, a test builds it by hand. No run-time cost. Not
taken: sub-structs alone (review 3: necessary, not sufficient, since handlers would still
take `App *`).

**D3. Five seams, each a struct of function pointers with one real implementation.**
`Clock` (already passed in; made total: no `clock_gettime` outside `main` and `prof`),
`Sink` (the terminal), `Conn` (channel and phones), `Spawner`, `Disk`. Cost: one indirect
call per syscall, nanoseconds beside the syscall. Not taken: `LD_PRELOAD` shims in tests,
which test the libc boundary and not the program's decisions.

**D4. The terminal is a non-blocking sink with a pending buffer.** Output is its own open
of `/dev/tty` (`O_WRONLY | O_NONBLOCK`), which is the only way round the shared description
`term.c:84-89` describes. The frame's bytes go to a pending buffer; the fd joins `poll` for
`POLLOUT` only while bytes are pending; a frame drawn while the last is still going out is
diffed against the last *delivered* front. Tradeoff: the renderer's "front is what the
terminal shows" becomes a statement about delivered bytes, and that is where a bug would
hide, so it gets a property test over random short writes. Fallback when `/dev/tty` cannot
be opened (output piped): today's blocking write.

**D5. Requests are budgeted.** A turn spends at most a fixed slice (2 ms proposed) on
requests, then handles keys and draws; what is left runs next turn. `REQUESTS[]` carries a
cost class, so the dispatcher knows a read from an edit. A read is never split across turns
(a split read needs a snapshot); instead D7 bounds what one read can cost.

**D6. One `REQUESTS[]` table and stable codes.** The table holds name, kind, where it is
allowed, argument shapes, cost class, a one-line doc and the handler; `is_edit`, `off_takes`,
`lonely`, `not_alone` and the 320-line chain become lookups, `help [VERB]` is printed from
it, and a test asserts AGENTS.md lists exactly its verbs. The verdict line gains a code
(`error R301 line 3: ...`) and so does each event; `--wait` matches codes. Text stays the
wire's default and JSON stays opt-in (review 2: JSON is 2.0 to 2.3 times the bytes).

**D7. Reads cost what was asked.** `status` prints `seq`; `wait 0` with nothing kept answers
at once; `changes SEQ [REGION]` prints the change sets kept in the event ring up to a byte
budget, saying `lost` past it, and is never built by diffing two maps; a `dump` with no
region above a square count answers with the bounds and a hint unless `dump all`; the key
moves behind `dump key`; `describe` takes a region or a filter.

**D8. An agent has a name, and an accepted job is undone by number.** *(as ruled, question
6)* A request may open with the line `agent NAME`; `vtt --ctl` writes it from `VTT_AGENT`
when that is set, so an agent never types it, and vtt sets `VTT_AGENT=job-N` beside
`VTT_JOB` for an agent it starts. No name is the name `cli`: reads and proposals are taken,
and `take`, `drop`, `propose` and `undo` on another name's job are refused with a code, so a
mistyped name fails shut instead of being credited to someone else. A job records its
taker; `job N undo` undoes an accepted job by number and plain `undo` means the caller's own
last one; `job N conflicts` lists what `cs_check` already knows; each landing stamps its
undo mark with name and job. `status` prints the caller's name as vtt saw it, beside `seq`.
**Waits are held one a name:** a second `wait` from a name answers the first (its `seq`,
code "superseded") and is held in its place, so an agent that is killed and tries again can
never lock itself out, and one agent's repeats cannot take every slot as they can today
(`ctl_hold`, `ctl.c:333`). Callers with no name share one slot. **vtt becomes the parent of
the agents it starts:** the double fork (`app_agent.c:126-130`) goes, the loop reaps with
`waitpid(WNOHANG)` on `SIGCHLD`, and an agent that dies returns its job to `asked` with an
event and its exit status on the GM's line (127 for a command that cannot run, HEALTH 39);
a deadline covers the one that hangs. Tradeoff: vtt now owns reaping, and an agent must
still be cut from the terminal (`setsid` stays). An agent's undo during the GM's review
stays allowed for now (question 5, HEALTH 49).

**D9. Sparse rows behind a file version, and the flush off the key.** A row that is all
void is written as a run in a new version; the writer still picks the lowest version that
says everything, so a map with no void row saves byte-identical to 1.x. A save on a key is
`write` and `rename`; the `fsync` runs after the frame, and on close and quit. Tradeoff: a
power cut inside that turn can lose the save the GM just asked for (the file is intact
either way, old or new). Question 3.

**D10. One copy-on-write overlay** (16x16 blocks, a bit a cell, as `checkpoint.h` has
today) serves the proposal's scratch map, the agent's checkpoint and `changes`. A proposal
then costs its changed cells, not the map. Tradeoff: every reader of a scratch map goes
through the overlay's lookup; the frame path never reads a scratch map except in a review.

**D11. The oracle is frozen from the 1.x binary before any 2.0 code.** A script runs 1.x
over every fixture, the fuzz corpora and generated maps and stores: `--check`, `--describe`
and `--dump-map` (text and JSON), load-then-save bytes, `--dump-frame` for each golden's
script at several sizes, each channel request with its answer, and the recorded wire
streams. 1.x first gains a cell-level frame dump (glyph, colors, attributes), about 30
lines, so color is in the oracle. 2.0 is then run against the same inputs and compared. The
field-poking tests are rewritten per module as it moves, not ported wholesale.

**D12. The privacy boundary stays two renderers, and gains a model.** Review 2: bounded by
the window and impossible to leak by omission; keep. Added: one function listing the GM-only
things on screen, so a test asserts on every simulated frame that none of them reaches the
players' cells.

**D13. The session log records requests.** One line per request (agent, verb, code) and the
change lines of each landing, bounded; on a fatal signal the event ring, the jobs and the
pending output's size are written out. A failed autosave is said once on the GM's line.

**D14. Phones.** A client more than N frames behind is marked stale and sent one FULL
instead of the queue; the frame buffer is sized from the window at resize; a close for
overflow is counted and said.

**D15. The docs separate truth from history.** Every still-true *As built* fact moves to
its CODEMAP row or the README and the design records are frozen; CODEMAP rows become *owns*
and *invariants* with no dates; `tools/lint.sh` runs under `make test` and turns the prose
invariants that can be a grep into one (each first shown failing on a seeded violation).

**D16. Small ones, taken as their file is rewritten.** The undo arrays become rings (the
trim is a 15 MB `memmove` today); the picker sorts then dedups adjacent; the agent starts
with `posix_spawn`; the per-frame creature questions get generation-stamped answers. An
index of creatures by block is **not** planned: 500 creatures cost 5 µs a frame.

**Not changing:** single-threaded (with D4 and D9 nothing left blocks); no dependencies; no
MCP server in the binary (a wrapper outside it reads `help json`); the proposal model
(scratch, the GM decides, all or nothing, one undo step); the event ring's `seq`, `lost`,
`reset`; the wire to the phones; the 20-byte undo op; the 16-byte `Cell`.

## Performance considerations

Machine for every figure: the desktop, i7-8700K, from review 2's runs, which were **not on a
quiet machine** (timings ±10 to 20%; bytes, allocations and RSS exact). Each row is measured
again on a quiet machine as its step is built, and both numbers go to PERFORMANCE.md.

| path | speed of light | 1.x today | 2.0 expects | the gap, and why it is accepted |
|---|---|---|---|---|
| a key's frame to the terminal | the changed cells' bytes, one `write` (~200 B, ~1 µs) | 207-298 B, ~22 µs of drawing | the same | drawing the whole window is 0.14% of a 16 ms budget; a dirty-region draw is not worth its bookkeeping |
| the same, terminal not reading | nothing lost, one more pollfd | the process blocks without bound | one `memcpy` of the frame's bytes into the pending buffer (~300 B) | none |
| a request's round trip | 3.1 µs on the socket + the work | ~1 ms with a process start; the work unbounded in the turn | the same per call; at most 2 ms of request work a turn | the 1 ms is the client process, kept on purpose (question 6): a stateless call is what an LLM's tool is |
| `dump` of a region | the region's bytes (`rows × (w+1)`) | + 330 B of key each call; 3.2 MB transient for a 530 KB answer | the region's bytes, one buffer sized from the region | none |
| "what changed since SEQ" | the cells noted since SEQ | a re-dump of the region (1.4 KB at 20x20) or of the map (541 KB) | the kept change sets' lines (~100 B for a dozen edits) | a fill is 2 MB of change set: capped, answered `lost`, the agent re-dumps |
| a proposal | its changed cells, before and after | a 786 KB copy (18-28 µs at 512x512) + 17 ns a changed cell | O(changed cells); ~2 ns a cell to note | the diff's 17 ns a cell (HEALTH B2) is the dedupe hash; measured again once the overlay supplies the cells |
| a save on a key | the bytes into the page cache (0.16 ms for 789 KB) | 1.18 ms writer + 2 ms `fsync` | writer in one buffer sized from the map; `fsync` after the frame | durability moves one turn later (question 3) |
| the file's size | ∝ content | ∝ canvas (789 KB for an empty 512x512) | ∝ content for void rows; unchanged for dense maps | dense rows of real squares stay one character a square: readable and diffable |
| a load | ~1 ns a byte | 3.4 ns a byte | ~1-2 ns a byte with 256-entry tables | to be measured; the loader is not on a key except a trip |
| a lagging phone | one FULL (20.5 KB at 200x50) | every queued DIFF (368 KB seen) | one FULL after N frames | none |
| starting an agent | one `posix_spawn`, tens of µs | 0.36 ms | tens of µs | none |
| creature questions a frame | the visible creatures | 18 ns a creature (117 µs at 5,000) | constant while nothing moved | the first frame after a move still walks the list |

Instrumentation: every row above gets a `PROF_ZONE` and a scenario in `tools/perf.sh`. New:
a `--bench-stall` that holds the terminal's fd; an allocation counter in the bench asserting
zero mallocs across a frame scenario's loops, run by `make test`; a bytes-to-phones column;
a `ctl.wait` row (HEALTH 8), possible once the loop is a function. Byte counts are asserted
in tests (they are exact); times are published, not asserted.

## Verification

Review 3's strategy, in build order; its section 3 has the detail.

1. **The oracle** (D11), stored before step 1 of the build.
2. **Properties on the pure modules**, each a seeded random loop in the shape of
   `test_fog_diff`: save and load round trips; undo all then redo all; `apply(diff(a,b),a)
   == b`; the overlay against a full copy; sparse against dense; the cached creature answers
   against the walk.
3. **Protocol transcripts** over `exec(World, request)`: a file per verb, codes matched,
   two clients for the job state machine. No sockets.
4. **Simulation** round `loop_once`: scripted keys, scripted `Conn` bytes, a fake clock, a
   fault schedule for `Disk` and `Spawner`. Scenarios: the stalled terminal, the stalled
   phone, four dumps in a turn, the dead agent, the failed save and autosave, the trip with
   jobs open. The privacy model asserted on every frame.
5. **End to end, few:** the scripted fake agent and the real-socket suites that exist, the
   page decoder in node, and one pty-driven run of the real binary.
6. **The lint** (D15).

The test objects compile separately (a change recompiles one file, not 84 for 50 s), and the
28 s kernel-buffer test is cut down by setting small socket buffers.

### The rulings, as the plan now reads them (2026-10-12)

The user's words are above; this is what each changes. Where a ruling is read one way out of
two, the reading is said.

1. **Rebuild the spine, carry the leaves** (D1 as written). The question offered two roads
   and the answer was "yes": it is read as yes to the plan's road, not the clean room.
2. **The map tools' output may change, but only for the better.** `--check`, `--describe`
   and `--dump-map` are compared with 1.x by the oracle (D11) all the same, and each
   difference is either a defect or a change written down with what it saves (bytes an
   agent reads, a duplicate dropped): the oracle's stored output is then replaced in the
   commit that makes the change, never wholesale. Nothing was said of the saved bytes or the
   file versions, so the plan's assumptions stand: a map that needs no sparse row saves
   byte-identical to 1.x, and all fourteen versions load.
3. **The flush moves off the key** (D9 as written).
4. **`MAP_MAX_DIM` stays 512.** Read as yes to the question asked. So the overlay (D10) and
   sparse rows (D9) are tidiness, not load-bearing: they keep their places in the build
   order (steps 3 and 5) and are the first things cut if a step runs long.
5. **An agent's `undo` during the GM's review stays allowed, for now.** HEALTH.md row 49
   carries the note to look at it again, and says when.
6. **One process a call, as today, with names; no persistent connection.** The user left
   the call to the planner, with an AI-engineering agent to weigh in; it did (Fable 5.1,
   2026-10-12) and the planner agrees. The client that matters is a stateless tool call: a
   fresh `vtt --ctl` whose only memory is text the model has already read. So the
   protocol's state must be text too, a name and a `seq`. A held `wait SEQ` is safe to
   repeat after a kill or a timeout; a pushed event goes to a process that may be dead, and
   making that safe needs a buffer with cursors, which is the event ring again plus a
   wrapper to keep alive. The millisecond a call costs is nothing beside a model's turn.
   What changes is the shape of the limits, in D8 below: designed for **four named agents**,
   four requests in flight (as now), eight held waits, and **at most one held wait a name**.
   Not built: a persistent or framed connection, pushed events, a registry of agents, an
   `--agent` flag beside the variable. A wrapper outside the binary (an MCP server) calls
   `vtt --ctl` like anyone else.
7. **The request tables and the agent's prompt are generated from `REQUESTS[]`,** on one
   condition, that it does not rot an agent's context. Held to by three rules: the table
   holds one line a verb and no prose; what is generated is committed text a test compares
   (nothing is built at read time, and no page grows a second copy of the table: AGENTS.md
   holds it, the README links to it); and `help VERB` answers for one verb, so an agent
   never has to read the whole table to use one.
8. **`make test-fast`** skips the socket and process suites; `make test` runs everything.
9. **With `:agent off` the channel refuses every request** with one coded line saying to
   type `:agent on` in that vtt, and naming its map so a caller with several vtts open knows
   which. This reverses CONFLICTS.md's decision 5, under which an off channel still took
   proposals, `status` and `wait`. The consequence to know of: `vtt map.vtt --apply plan.txt`
   against a map a GM has open with the agent off is refused with that line, where 1.x
   made it a proposal. It does not fall back to writing the file under the GM. 1.x is left
   as it is; HEALTH.md row 15 records the ruling.
